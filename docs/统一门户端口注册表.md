# 统一门户端口注册表

`deploy/platform-ports.env` 是本地统一能力门户及其十二个项目浏览器入口端口的唯一注册表。它只管理浏览器可访问的宿主机端口；数据库、Kafka、Redis 和项目内部服务端口仍由各项目独立管理。

## 修改端口

只编辑：

```dotenv
AUTH_PORTAL_UI_PORT=5274
AUTH_CONSOLE_UI_PORT=5273
LANGCHAIN4J_UI_PORT=8093
RECSYS_UI_PORT=9095
DROOLS_UI_PORT=8095
RISK_UI_PORT=15173
WORKFLOW_UI_PORT=8302
RECON_UI_PORT=8088
BENEFIT_UI_PORT=8083
MARKETING_UI_PORT=8084
TRADE_UI_PORT=4180
WMS_UI_PORT=18180
OA_UI_PORT=8404
```

修改后执行：

```bash
./deploy/platform-ports.sh sync
```

该命令会：

1. 校验所有值是 `1-65535` 内互不重复的整数；
2. 同步 `project-portal/public/config/catalog.json` 的 `launchUrl` 和 `healthUrl`；
3. 解析十一份 Docker Compose，确认实际发布端口与注册表一致；
4. 发现缺项、重复端口、目录漂移或 Compose 未接线时立即失败。

授权管控台由 Vite 监听 `AUTH_CONSOLE_UI_PORT`（默认 5273），交易中心运营台由 Vite 监听 `TRADE_UI_PORT`（默认 4180），都没有控制台 Compose 映射，因此 `check` 不同步校验这两个端口。WMS 仓储管理台由 `wms-platform` 的 `console` 服务发布，`WMS_UI_PORT` 对应 `WMS_CONSOLE_HOST_PORT`（默认 18180）。OA 协同办公平台由 `oa-platform` 的 `oa-console` 服务发布，`OA_UI_PORT` 对应 `OA_CONSOLE_PORT`（默认 8404）；门户入口为 `:8404/login`。交易 API 仍由 `transaction-center/deploy/compose.yaml` 的 `TRADE_HOST_PORT` 管理；WMS 入/出/库存/履约 HTTP 仍由 `wms-platform` 各服务端口管理，均不属于门户入口。

脚本不会寻找“下一个空闲端口”。端口被其他进程占用时，项目启动应失败并要求释放占用，这样门户地址不会静默变化。
`sync` 不会擅自重启业务容器；端口变更后用下节的统一 Compose 命令重建受影响服务，Docker 会按新发布端口重建容器。

## 启动方式

auth 一键启动会自动同步目录：

```bash
./dev.sh up
```

也可以从 auth-platform 统一调用任一项目 Compose：

```bash
./deploy/platform-compose.sh auth up -d project-portal
./deploy/platform-compose.sh langchain4j up -d capability-showcase-frontend
./deploy/platform-compose.sh recsys --profile console up -d console
./deploy/platform-compose.sh drools up -d gateway
./deploy/platform-compose.sh risk --profile apps up -d risk-console
./deploy/platform-compose.sh workflow up -d console
./deploy/platform-compose.sh recon up -d console
./deploy/platform-compose.sh benefit up -d console
# 权益发放中台走 Casdoor 时叠加：
./deploy/platform-compose.sh benefit -f compose.secure.yml up -d --build
./deploy/platform-compose.sh marketing up -d console
# 营销低代码平台走 Casdoor 时叠加：
./deploy/platform-compose.sh marketing -f compose.secure.yml up -d --build
./deploy/platform-compose.sh wms up -d console
./deploy/platform-compose.sh oa --profile apps up -d oa-console
```

各仓库常用启动脚本也会在同级目录布局下自动加载中央注册表。独立 checkout 找不到 auth-platform 时保留当前默认端口，以免破坏各仓库独立 CI；统一工作区内不要再通过项目私有 `.env` 覆盖 UI 端口。

## 新增门户项目

新增项目时必须同时完成：

1. 在 `platform-ports.env` 新增唯一的 `<PROJECT>_UI_PORT`；
2. 目标 Compose 的宿主机发布端口引用该变量；
3. `sync-platform-catalog.mjs` 增加项目 ID 映射；
4. `platform-compose.sh` 增加仓库/Compose 映射；
5. `platform-ports.sh check` 增加服务和容器端口断言；
6. 更新 portal catalog 后运行 `./deploy/platform-ports.sh sync`。
