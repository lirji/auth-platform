# P7 本地加固验收契约

依据现有v0.2 P7与EXECUTION_DAG，用户在P6交付后指示“继续”。授权本地隔离验证与正常Git交付；原商城、共享Casdoor和OA既有用户改动保持。P7-08生产观察不由本轮推导授权。

## 顺序与边界

1. P7-01真实端点/凭证/数据库角色清单及最小权限探针。
2. P7-02复用Micrometer，中央请求指标只用有限operation/outcome标签；ALLOW、DENY、AUTHN、ERROR、INVALID、CONDITIONAL可区分。内部管理指标不自动公开；默认仍仅health。日志不记录请求体、Token或凭据。
3. P7-03固定合成夹具、至少两个独立auth进程；有界并发与请求数、真实P50/P95/P99及失败数量。未确认生产指标只报告测量，不声称SLO通过。
4. P7-04复用P3进程CAS/未知结果故障测试，补双HTTP实例kill恢复、实时撤权与独立故障代理。不得停止共享组件模拟故障。
5. P7-05隔离服务凭证分阶段轮换，新旧实例观察窗口明确；窗口结束旧凭证在所有新实例拒绝。用户签名密钥轮换与服务凭证轮换分开记录，缺一不可冒充全部通过。
6. P7-06新建隔离PG恢复目标和新图存储；导入备份后默认离线，备份后撤权日志齐全才继续。恢复重建前旧token/marker不可用，分区非READY；重建后新图水位及允许/拒绝实际检查通过。不能覆盖旧库或从未知日志缺口推断安全。
7. P7-07逐项门禁和可执行手册；真实Owner、容量接受和生产配置未定保持HOLD。P7-08只有实际上线和观察证据才能DONE。

## 资源与保留

运行进程只监听回环；新库、代理和图容器有任务唯一标识，限制并发、超时、批大小；秘密文件0600。auth检查、管理及投影采用独立进程/连接池预算。工具只停止自己创建的进程和容器，不删除演练库或私有证据。文档只记录配置键与位置。

用户容量决定：先做本地有界基线，生产目标待定。固定并发1/4/8、每档48请求、2个auth JVM；报告全部延迟/错误，不执行未授权的生产压测。
