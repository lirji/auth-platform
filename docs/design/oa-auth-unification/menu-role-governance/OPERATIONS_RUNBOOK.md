# 菜单与角色授权治理运行及恢复手册

本手册对应已实现MG00–MG19和各片冻结契约。代码交付不代表已部署：本轮未更新原5273／Commerce运行实例、未部署生产。测试与生产使用独立权限实例及数据库；机器发布默认关闭，生产接入须明确目标与部署授权。

## 页面入口与职责

| 入口 | 使用者与操作 |
|---|---|
| `/governance/menus` 菜单权限 | 查看关联项目真实菜单、层级、路由、能力及角色关联；选择当前应用／组织／环境。菜单改名、移动和隐藏本身不会撤销权限 |
| `/governance/catalog` 权限目录 | 当前HUMAN Owner预览完整差异、决定授权影响、固定依据发布，查询发布历史／来源／漂移；必要独立诊断资格单独核验 |
| `/governance/roles` 角色管理 | 创建固定版本、查看差异及显式授权迁移；旧版本保持历史，新版本不会自动替换既有授权 |
| `/governance/grants` 成员授权 | 明确来源／范围／期限的授权和严格撤权，查询实际完成回执；其他来源独立核对 |
| `/governance/personnel` 人员变更核对 | 当前管理＋独立诊断资格查看人员事实／不可变变更／当前和历史来源，按页明确选源创建人工复核 |
| `/governance/reviews` 权限复核 | 查固定任务、负责人、原与当前依据，逐项保留／调查／撤销，实际完成后确认；明确改派、取消未处理项 |
| `/governance/requests` 申请与通知 | 本人旧OA批准来源申请升级，必须重新审批；固定原范围／原截止，新批准不等于已完成切换 |

Owner发布权、管理委派、独立人员诊断资格和本人业务访问分别核验。角色、申请／组／个人来源和实际资源判权解释不同；不能凭菜单可见或任务COMPLETED推断所有资源ALLOW。

## 菜单变更与发布

1. 在Commerce声明同源处维护稳定菜单code，导出固定提交的候选制品；新增业务能力有稳定编码及资源／风险语义，不能重用旧编码改变含义。
2. 固定目标实例／环境、声明、提交、制品摘要；查看新增、删除、名称、层级、顺序、路由、权限绑定差异及非法变化。新入口复用已有能力可能立即影响已有用户，新能力仍需独立授权。
3. 涉及既有人权限语义时由当前Owner明确业务原因和处理决定；分区人员影响必须当前管理＋独立诊断资格，完整性不足不表示无人受影响。
4. 采用GUARDED应用固定preview_id与原command_id发布。基础版本、依据或权限变化返回409／403，重新读取和业务决定，不能自动换键或内容。
5. 发布成功只说明目录已提交。查询来源／双摘要／发布历史及政策投影；没有受信运行核验时UNKNOWN，不能把源码commit或目录版本当生产制品证明。

CI受限机器只能发布指定应用／固定目标的允许候选，需Owner处理的变更不会自动发布。完整配置、默认关闭和原检查点恢复见[PUBLISHER_RUNBOOK](PUBLISHER_RUNBOOK.md)。

## 角色升级、人员变化和复核

- 迁移明确选择具体来源，固定原范围、代际、期限和目标角色，先撤旧→真实COMPLETED→授新→真实确认。任务持久化，页面关闭／进程退出后按原任务继续。不能强求无授权间隙或以SQL状态代替实际图证明。
- GROUP仍是同一组的动态授权，不展开为个人DIRECT；成员退出或加入遵循当前目录资格。OA升级使用新的有效批准并固定原截止，不能复用旧APPROVED解释成新版批准。
- 调岗／离职按OA权威事实核对当前成员和主体；不自动按岗位授新。目录冲突／隔离／source_sync UNKNOWN由目录负责人处理，本地检查点不是源端同步成功证明。
- 人工复核固定本页已选1–100条来源、原成员代际和负责人，不包含其他页或以后新增来源。KEEP只记录意见；INVESTIGATE待调查；REVOKE发严格撤权，GROUP影响全组必须另确认。
- 确认只接受本条原撤权命令的真实COMPLETED与版本／操作证明。取消不恢复已发撤权；WAIT_REVOKE可在取消或目标变化后继续确认。负责人失权时由当前合格管理者明确改派并记原因。
- 源码回退、取消迁移、撤销复核都不恢复已撤来源或撤销已经授出的新来源。恢复授权是新的业务决定，必须遵循对应来源、批准、范围、期限和当前资格。

## 故障处理

| 现象 | 处理与停止条件 |
|---|---|
| 401／403 | 检查当前可信client／audience、主体／成员代际、准入、委派／独立诊断及负责人；不换租户或扩大权限规避拒绝 |
| 409 | 重新读取当前版本、依据及来源事实，区分原命令已提交回执与新的业务决定；不得把原命令改体后重试 |
| 503 IdP | 查看私密日志与trace_id，检查固定发行方版本、JWKS和实时introspection。公钥缓存不豁免当前发行方／Token事实；依赖不可判定不能认证或复用旧ALLOW |
| 503 授权图／栅栏 | 核对图连接、POLICY／DIRECTORY状态、desired/applied水位和持久操作。恢复原可靠投影，保留租约和marker；不直接改READY／ACTIVE、删marker或绕过栅栏 |
| 发布或写决定结果未知 | 保留原目标／候选／命令／检查点，当前身份有效时查询原回执或同键同体重试。依赖恢复不代表先前请求未提交；不换键重复副作用 |
| 任务进程退出 | 新进程读取PG任务／条目／原意图并重新核验当前资格；图提交而SQL回执缺失由可靠投影恢复marker，不重建旧授权 |
| 页面读取失败 | 旧内容和写动作隐藏，显示拒绝／冲突／暂不可用，通过明确刷新重读；前端不能编造零影响或成功 |

故障期间先保留私密证据，确认是配置、身份、数据库、图投影还是业务冲突，再恢复对应依赖／原命令。共享组件的重启和生产操作需该目标明确授权，不用演练脚本修改共享服务。

## 回退与恢复的四种操作

| 操作 | 允许范围与验证 |
|---|---|
| 程序回退 | 使用明确旧制品，保留追加迁移与历史；验证其理解GUARDED、生命周期终态、来源谱系和新旧共存。不能恢复不理解当前门禁的旧写节点，不删除已应用V21–V36或假造迁移历史 |
| 目录修正 | 以更高版本发布合法修正，固定新的预览和命令；原版本与双摘要保持，指针不能降低；已RETIRED编码不能复活，展示修正不补授权 |
| 授权补偿 | 按新的受审计业务决定单独授予／撤销具体来源；核对GROUP和OA批准、原期限／范围与其他来源，不以回滚镜像恢复Grant |
| 数据恢复 | 备份及配置在明确隔离目标恢复，验证迁移、身份配置、任务／投影／审计及业务查询；原目标数据不能被演练覆盖。需授权后才做真实恢复，没有本片实测RTO／RPO结论 |

能力先弃用限制新增引用，再正式退出来源、未完成申请／迁移、组和策略／委派；最终退役须独立受信运行证明。生产部署核验器未接入时UNPROVEN阻止退役；弃用／紧急停用依照独立流程，不能用签名夹具声称生产API已退出。
