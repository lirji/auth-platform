# P1-06 停用契约细化

沿用已批准 P1 的当前状态、版本、幂等与事务审计要求。P1-06 首先提供受控收紧命令，供后续 OA 来源适配复用；P1-04 来源注册、P1-05 重新邀请/加入、P4 管理授权各自保持原节点，不将本片标为这些能力已完成。

## 入口与权限

新增离线 `LifecycleCli`，复用治理库所有者与 0600 配置文件的受控操作入口。不会新增未获管理授权的 HTTP 写接口。操作身份和范围从配置 `lifecycle.operator-ref`、`lifecycle.scope` 取得，不能从命令体伪造；scope 为规范租户 UUID 时只能停用该企业成员，为保留非 UUID 编码 `GLOBAL` 时只能停用全局主体。两类命令不能混用。此边界面向具有专用治理库操作权的运维，不向终端用户开放数据库或配置文件。

命令文件仅允许 `command.id`、`target.id`、`expected.version`、`reason`；ID 规范 UUID，版本为正整数，原因 1–1000 字符且不能含控制字符。操作由显式子命令 `suspend-member` 或 `suspend-principal` 选择。作用域、操作者、操作、目标、预期版本和原因都进入规范摘要。

## 状态与并发

- 成员：仅 `ACTIVE → SUSPENDED`，版本 +1、代际不变。必须同时匹配目标成员、配置中的租户、预期版本及当前状态；其他企业不可操作。
- 主体：仅 `ACTIVE → SUSPENDED`，主体版本 +1；其所有租户成员记录保持原样，但 P1-03 当前主体检查拒绝这些身份。
- 不实现隐式恢复，不把停用当离职，不通过重新 bootstrap 绕过停用。命令失败使用既有 INVALID_ARGUMENT、MEMBERSHIP_UNAVAILABLE、VERSION_CONFLICT、COMMAND_CONFLICT；不增加错误协议。
- 使用已有命令唯一键及行锁。同键同摘要返回同一目标的当前状态；同键异内容拒绝。不同命令竞争同一旧版本，最多一个成功，失败方不得留下命令或审计。
- 状态修改、版本变化、命令回执和追加审计同一数据库事务。审计必须包含操作者、范围、目标、命令、原因、前后状态/版本与数据库时间；审计失败全部回滚。无远程请求在事务内。

## 数据演进与验证

新增 V2 扩展现有审计表，V3 要求新停用操作完整填写审计字段，历史记录允许缺少新字段，新生命周期写入完整前后信息；不修改 V1、不更新历史审计。旧列和旧命令协议保留。回滚应用代码不会恢复已停用状态，数据库增量列保留。

真实 PostgreSQL 验证租户边界、幂等、异内容冲突、旧版本竞争、全局与局部停用区别、审计失败原子回滚。真实 HTTP 验证通过受控命令停用后，仍有效的旧 JWT 无法取得上下文。OA 从源端离职到接收命令之间的延迟和确认由 P1-04 处理；本片不声称 OA 已经完成全链路撤权。
