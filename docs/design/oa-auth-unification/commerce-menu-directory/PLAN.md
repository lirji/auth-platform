# 电商实际菜单目录补齐

用户纠正上轮页面不展示电商实际菜单。目标是在5273显示当前电商真实中文分组、页面、路由及权限/角色关联，并将完整已实施Owner目录发布到本机。原账号、业务授权和委派不扩权；不修改正在进行其他任务的Commerce工作区。

## 未知项与决定

- 本机目录仅2个示例菜单；中央业务导航的6组35页面及1个商品协作入口未发布。菜单元数据来自Commerce已提交的`frontend/src/iam/navigation.ts`和既有已验证Owner映射，读取不可变Git内容并核对运行源码，不使用未提交变更。
- 原manifest v1仅存code/parent/route/any_of，没有中文名称。输入兼容新增label/position，发布时将显示元数据与原权限清单分离持久化、同事务同版本提交。旧manifest JSON和SHA归一化保持逐字节不变，旧后端可继续读取，不引入第二权限来源。
- 新V20只增版本绑定的不可变菜单展示快照，FK绑定原application_manifest；全部SQL与注释在持久化层。原历史迁移不改。
- 重试同版同时核对权限摘要和显示快照；名称/顺序不同必须新版本。Owner资格复用现有当前身份校验。publishedCatalog单SQL基准包含展示快照并在返回前重验。
- UI显示数据库返回的中文名称和原编码，按Owner导航顺序排列；无显示元数据的旧菜单回退编码。菜单浏览不产生Grant。跨页角色索引沿用上轮完整实现。
- 本机新目录保留既有3能力的原资源/风险、旧菜单和角色/Grant；只新增经过既有Owner终验的菜单/能力。新增能力超出原委派时明确显示不可授予。

选型/架构/影响Gate PASS：现有Java/MyBatis/PostgreSQL/React/AntD，不加依赖或中间件。显示元数据与判权独立，使旧后端回滚兼容新目录。无需要用户选择的技术未知。
