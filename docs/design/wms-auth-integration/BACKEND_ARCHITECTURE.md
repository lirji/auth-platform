# WMS 接入边界与影响

## 权威与依赖

Casdoor → Auth 已验证主体/成员 → 固定 WMS 服务身份 → WMS 资源 Owner。Auth 的 principal/membership/tenant UUID 与 WMS enterprise_id 是不同标识，必须通过受控映射关联，禁止把 owner 字符串或浏览器提交值当作中央租户。

Auth 复用现有角色、Grant、严格投影和 ScopePlan。WMS 复用 wms-security、原 Controller/Mapper、OIDC 和控制台；不增加数据库、MQ、缓存或新的权限中心。

## D-RESOURCE：仓库资源采用精确资源范围

新增两个封闭资源类型：wms_warehouse 和 wms_enterprise。wms_warehouse 的 resource_id 就是仓库标识，只支持 SPECIFIED_RESOURCES；这使现有协议能够表达仓范围，无需增加 warehouse_id 字段或把仓库伪装成门店。wms_enterprise 只支持 TENANT_ALL，用于确实属于全企业的共享资源。

每次必须用同一 Grant 的能力与范围路径；宽读取范围不能扩大另一个写权限。仓库不接受 TENANT_ALL，避免已有角色隐式取得将来新增仓库。调用服务还须在 scope.owner 中显式登记资源所有权。

## 兼容与失败

旧资源、ScopeDtos 格式、规则版本 1 不变；旧消费方不登记 WMS 应用，不接收新类型。新消费方必须固定包含新绑定的 SDK 来源，先发布 Auth 再交付 WMS。旧 SDK 遇到新类型继续拒绝，不能降级成全企业。

授权拒绝与依赖失败分别返回既有 403/503 语义。后续切换默认关闭，在真实闭环验证后才能启用。先检查当前授权再使用可信 Owner 的企业/仓库/单据事实；任何业务提交与远端撤权之间的窗口必须在对应写片记录，不能以 JWT TTL 宣称立即撤权。

## 影响分析

- 本轮已冻结 W00–W02：协议新增资源 allowlist、行为测试、源目录生成器和设计/进度文档；不改数据库、图 schema 或现有配置。
- W03：组织输入确认后冻结身份映射与接入运行契约；未确认时不得创建成员或授予角色。
- W04：主数据/库存只读，包含仓库列表 SQL 过滤、本人菜单与深链、真实旧令牌撤权验收。
- W05：入出库命令，保留既有幂等和状态迁移。
- W06：盘点/调整/调拨，分别核验源仓、目标仓、审批/执行动作；调拨列表/详情需显式 Owner 范围适配，不能只加入口判权。
- W07：全链路、故障、兼容回归；本机部署须绑定验收制品并保留回退镜像，生产不在授权内。

逻辑边界不变，不进行服务拆分。组织映射是当前唯一已确认的必要业务待答问题；完整运行/消费契约在 W03 冻结前不得伪称完成。

## 用户答复后的接入边界

local-wms 与 ENT-DEMO 明确绑定；现有治理管理员作为显式 Owner，专属 Casdoor 4.11 业务身份与旧 WMS 身份隔离。Auth server 部署既有中央判权入口，不改变领域/数据库归属；Docker 跨网络 HTTPS，宿主回环验收沿用现有例外。WMS 单请求中央上下文适配现有 Controller/Mapper，按每个动作应用精确仓集合，企业动作的仓副作用另判仓能力。当前准入与已接受异步业务效果的边界见 CONTRACTS；关闭开关不改旧模式，开启后无旧 JWT OR 回退。W03–W07 架构/影响 Gate PASS，验证不得提前计完成。
